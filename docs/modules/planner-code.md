# Planner export code

## Purpose

Export a build as the code / URL of the official Wheel of Destiny planner
(`https://www.test.tibia.com/community/?subtopic=wheelofdestinyplanner&code=…`), including gems (D15). The test-server planner is used until tibia.com has the new wheel (D39, `npm run check:planner`). Pure TS,
no WASM at runtime. Codes are **byte-identical** to the planner's own `getCode()`.

## Files

| File | Role |
|------|------|
| `src/data/wheel/plannerCode.ts` | `encodePlannerCode`, `decodePlannerCode`, `plannerUrl`, `plannerVesselIssues`, `vesselQuality`, `sliceIdForGrid` / `gridForSliceId`. |
| `src/data/wheel/plannerCode.fixtures.ts` | Codes generated by the planner WASM with the configs that produced them. |
| `src/data/wheel/plannerCode.test.ts` | Fixture tests (always) + 200-build round trip against the WASM (skipped without `scripts/.cache/wod/skillgrid.cjs`). |

Dependency: `fflate` (inflate only, for decoding). Encoding uses a built-in deflate (below).

## Format

```
<V><ver><base64url(rawDeflate(payload))>      e.g. K1Y2BABkwM2MB_HAAA
```

- `V` — vocation letter: `K` knight, `P` paladin, `S` sorcerer, `D` druid, `M` monk.
- `ver` — `1` current, `0` legacy (older planner; `updateByCode` returns 0 and keeps only the tiles).
- Body — URL-safe base64 (`-`, `_`), **no padding**, of a **raw deflate** stream (no zlib header/Adler).
- Payload (version 1, 60 bytes):
  - bytes `0..35` — promotion points per slice, indexed by **grid id** (row-major 6×6, = `WheelTile.gridId`),
    one unsigned byte each (0..200). Independent of fill order.
  - bytes `36..59` — 8 vessels × 3 bytes `[basic1, basic2, supreme]` in vessel id order; `0xFF` = empty. Values
    are the planner's mod keys, **identical to `mods.basic[].id` / `mods.supreme[].id` in `wheel-data.json`**
    (no mapping needed). No grade is stored (the planner always uses grade IV).
- Version 0 payload: 36 tile bytes + 12 vessel bytes; the current planner ignores those 12 bytes entirely.
  D88: this is the live planner's format (www.tibia.com): 4 domain vessels × `[basic1, basic2, supreme]` in quarter
  order TL, TR, BL, BR. Any gem may sit in any vessel; mods fill the slots in order (basic1, then basic2, then
  supreme). `encodePlannerCode({ variant: 'live', … })` writes version 0, `decodePlannerCode` returns
  `variant: 'live'` and `plannerUrl` opens the live planner for it. Same compression; 300 random builds matched the
  live planner's codes byte for byte during development. For some repetitive 48-byte payloads zlib-ng picks a
  dynamic-Huffman block, so the planner's own string differs while the payload is the same; the planner loads both.
  `src/engine/live.test.ts` (WASM-gated) checks that the live planner loads optimizer codes with the same payload,
  resonance, gems and damage & healing.

### Compression

The WASM embeds **zlib-ng 1.3.1** (compat API) and compresses at level 9 (`deflate_slow`: lazy matching, 3-byte
rolling hash, longest match with nearest candidate on ties, never matching window position 0). For 60-byte payloads
zlib-ng always emits a single fixed-Huffman block. `deflatePlanner()` re-implements exactly that token choice;
Node's zlib (Chromium fork) and pako produce valid but different streams for ~2/3 of codes.

### Planner validation (`updateByCode`)

- Returns `1` (ok), `0` (legacy version), `-1` (rejected — then nothing is loaded).
- Rejects the whole code if a slice exceeds its capacity or has points while not unlocked (unlock = a neighbour on
  the unlock graph is **completely** filled; partial points unlock nothing).
- Gems: silently **drops** a gem whose slot pattern does not match the vessel quality (lesser = `basic1`, regular
  = `basic1+basic2`, greater = all three) or whose basic mod is not allowed in that slot. It **keeps** gems on
  vessels that are not unlocked yet, duplicate basic mods and supreme keys of other vocations — `plannerVesselIssues`
  flags the slot/vocation problems; `encodePlannerCode` throws on them unless `{ strict: false }`.

## Engine mapping

Engine slice id (`Slice.id`, `src/engine/wheel/build.ts`) is the planner tile enum name (`QTL0..QBR8`) =
`WheelTile.tileName`. Use `gridForSliceId(sliceId)` / `sliceIdForGrid(gridId)` to build `points`
(the layout is identical for all vocations). Vessel ids are `WheelVessel.id` (0..7, quality fixed per id).

```ts
encodePlannerCode({ vocation, points: { [gridForSliceId(id)]: pts, … }, vessels: [{ vesselId: 2, basic1, basic2, supreme }] })
```

## Verification

Reverse-engineered by driving the WASM (`SkillwheelPlanner`) in Node and varying one thing at a time
(vocation, 1/2/3/50 points on single tiles, fill orders, mods per vessel/slot) and inflating `getCode()`.
`plannerCode.test.ts` checks the committed fixtures and, when the WASM cache exists, 200 random valid builds
(random fills/partials in unlock order, random gems on all qualities, all vocations): the planner built through
its API yields exactly our code, `updateByCode(ourCode) === 1` reproduces identical tile points and mods, and
decoding the planner's code gives the original build. During development 500 further random codes matched
byte for byte.
